# Read-only readiness default experiment — rejected

The proposed addition preferred read-only default manual checks and separate, explicitly authorized recording/repair. It addressed the historical helper-journaling failure, but the current guidance already led both models to produce that design in this experiment. **Reject the additional source text in this batch:** all four generated helpers passed the same eight execution cases, so no incremental benefit was observed. Both proposed source files were restored exactly; the patch and frozen sources remain retained as rejected evidence.

The eight cases were fixed before generation: intact input, protected drift, missing protected source, a legitimate unpinned task output, missing journal, authorized recording, authorized recording of failure, and malformed pins. Four fresh contexts (baseline/candidate × gpt-6.1-sol/gpt-6-luna) received the same prompt and construction scope. Parent inspected the generated code, then actually ran it in 32 separate local copies. Ordinary checks reported correct exit status without changing files or directories, including failure/missing-journal cases. Recording only appended truthful boolean outcomes to the journal and preserved historical bytes. Builders changed only helper/usage files; pinned inputs, journal, empty Git indexes and unborn histories were preserved. Actual root models matched requests; reasoning/cost unknown.

The [evidence summary](improvement-readiness-default-2026-10-24.json) binds every helper/run and parent results. Final case-file identities were collected as a separate terminal observation; the original parent assertions record actual deltas, exit codes and output and were not retrofitted. This qualifies the eight stated toy cases, not every possible helper input, hostile symlink, concurrent race or full installation. Recording flags do not enforce or create caller permission. A single sample per model/revision cannot establish a reliability percentage or that prior failures never recur. The experiment supports retaining the existing concise guidance; it does not establish that read-only defaults are a bad design.

Independent disposition/report review and protected delivery remain required. No rejected helper guidance or generated toy helper is to be installed into AgentOS main. Sandbox cleanup remains owned until the final candidate finishes.
