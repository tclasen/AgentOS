# Procedure

1. Reconcile target repository state and permissions immediately before editing; avoid conflicts with new user changes.
2. Create/integrate a minimal role-aware root `AGENTS.md`: unassigned interactive session activates the root Director; delegated workers preserve assigned roles. Respect existing instructions.
3. Install a compact organizational home, preferring `.agentos/` but following approved runtime conventions. Implement permanent Director and Chief of Staff; only justified additional roles. Use native structured definitions where practical, Markdown where freeform.
4. For each selected component and hard dependency, establish a **working pathway** (activation, responsibilities, tools/permissions, persistent evidence if needed, verification). Before writing, enumerate its distinct **Operational contract**, **Implementation** and **Verification** obligations, then map each to actual target instructions or mechanisms. A single row saying a component is present, a heading or a role name is insufficient. Consolidation must preserve the individual obligations. Use the required operating checks in [qualification](qualify.md) to catch omissions before declaring the files finished. In particular, the mandatory improvement loop needs an executable evaluation step, retention of accepted/rejected/inconclusive outcomes and a scoped rollback path, not just a suggestion that a change could be checked. These may share an existing small file; no separate service, ledger or experimental framework is implied. Do not copy the full installer knowledge catalog or generate unused placeholder files.
5. Preserve constitution, grants, sensitive data separation, operational fact/unknown distinction, authorized boundaries and user work. Minimize duplicated canonical rules and top-level clutter.
6. Do not claim nonexistent background execution, universal instrumentation, independent sandboxing, locks or idempotence. Implement approved fallback or report a missing capability.
7. Record sufficient installation provenance/selected capabilities when approved; make the installed CoS capable of reconfiguring the organization without this source repository.

# Transition

Run [qualification](qualify.md) to the approved depth. File generation alone is never proof of operational behavior.
